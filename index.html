Vanny's Module: Architecture & Tables Reference

Official spec mapping from B2B_Module_Developer_Implementation_v2.md
Assigned Developer: Vanny
Module Responsibility: Buyer-side workflow & PO Integration
Core Tables: b2b_transaction, inv_purchase_order, inv_purchase_order_status_history
1. b2b_transaction (Root Record)

Root record for one buyer-supplier transaction. Identifies the two parties and overall process.

ColumnTypeNotes
idBIGINT AUTO_INCLocal DB ID only
uuidCHAR(36) UNIQUEGlobal cross-db identity
transaction_noVARCHAR(50)e.g. B2B-2026-000001
buyer_branch_uuidCHAR(36)Buyer stable identity
supplier_branch_uuidCHAR(36)Supplier branch identity
supplier_connection_idBIGINTNULL for same DB; ID for remote
statusVARCHAR(30)OPEN, COMPLETED, CANCELLED
2. inv_purchase_order (B2B Extension)

Buyer's actual purchase order linked to B2B collaboration.

ColumnTypeNotes
idINT AUTO_INCLocal buyer PO ID
b2b_transaction_idBIGINTLinks PO to B2B transaction (NULL for legacy)
branch_idINTBuyer receiving branch
supplier_idINTLegacy only! Set NULL or ignored for B2B
po_numberVARCHAR(50)e.g. PO-2026-00125
is_approveTINYINT(1)Internal PO approval (separate from B2B)
3. inv_purchase_order_item

Buyer's ordered lines with strict composite primary key.

ColumnTypeNotes
(po_id, item_id)COMPOSITE PKNEVER create fake PO item ID!
qtyDECIMAL(14,4)Requested quantity
priceDECIMAL(16,6)Requested unit price
unit_idSMALLINTUnit of measure
4. inv_purchase_order_status_history

Permanent, immutable audit trail of every status transition.

ColumnTypeNotes
idBIGINT AUTO_INCPrimary key
po_idINTLinked purchase order
old_statusVARCHAR(30)Previous state
new_statusVARCHAR(30)DRAFT, SENT, NEGOTIATING, CONFIRMED...
actor_typeVARCHAR(20)BUYER, SUPPLIER, SYSTEM
noteTEXTReason or event context
